# SM90 mixed G32 deployment

This branch adds native CUDA/CUTLASS execution for compressed-tensors checkpoints
with WFP8/AFP8 G32 Linear layers and WINT4/AFP8 G32 MoE experts. It targets H20
(SM90), BF16 intermediate activations, and tensor parallelism. It retains the
existing SM90 QKV FP8/FlashAttention 3 path and reasoning_content serialization.

## Quantization and loading

Keep the checkpoint's quantization_config. Do not remove input_activations,
change group_size, or convert the scales to FP8. Linear weights use FP8 E4M3 with
original FP32 [N,K/32] scales; MoE uses packed symmetric INT4 with original BF16
[N,K/32] scales. Both activations are quantized dynamically in original K groups
of 32. Intermediate scale arithmetic uses FP32; MoE scales expand losslessly.

`--linear-backend auto --moe-backend auto` detects these exact configurations.
`--linear-backend cutlass_g32 --moe-backend cutlass_g32` selects them explicitly.
Unsupported configurations fail rather than silently using a different group.
Each TP shard's original K offset and K length must be divisible by 32. Fused
column projections load and slice each source scale independently. FC2 activation
groups follow the local, aligned intermediate shard; TP reduction remains outside
the expert GEMM. Router probabilities are applied once during unpermutation.

Supported: SiLU gated MoE, up to 256 experts, tensor parallelism, CUDA Graph,
FP8 KV cache. Expert parallelism and router weights applied to FC1 inputs are
explicitly rejected. The G32 kernels do not implement Triton or QDQ fallbacks.

## Launch

The validated checkpoint is Qwen3.5 MoE even though its directory name includes
Qwen3-next. Its MTP experts are also quantized. Use `qwen3_5_mtp` (v0.29 accepts
this alias and normalizes it to `mtp`), not `qwen3_next_mtp`. With MTP, use
`--mamba-cache-mode align`; upstream does not support `all` for this combination.
Vision and prefix caching are retained. Upstream v0.29 defaults to the V2
runner, which passes zero common-prefix length and therefore does not actually
execute cascade attention. Cascade is also disabled by default in the upstream
model config. To opt in, pass `--no-disable-cascade-attn`, set
`VLLM_USE_V2_MODEL_RUNNER=0` and, with MTP, add `--no-async-scheduling`.
These select the upstream V1/synchronous
execution path; measure its speed separately from the default V2 runner. No OMP_NUM_THREADS
value is forced by this branch; the upstream worker policy still applies.

```bash
VLLM_ENV=/root/miniconda3/envs/vllm
export PATH="$VLLM_ENV/bin:$PATH"
export CUDA_HOME="$VLLM_ENV"
export CPATH="$VLLM_ENV/targets/x86_64-linux/include${CPATH:+:$CPATH}"
export LIBRARY_PATH="$VLLM_ENV/targets/x86_64-linux/lib:$VLLM_ENV/lib:/usr/lib/x86_64-linux-gnu${LIBRARY_PATH:+:$LIBRARY_PATH}"
export CUDA_VISIBLE_DEVICES=0,1
# Set MODEL to the mixed G32 checkpoint directory.
vllm serve "$MODEL" \
  --served-model-name Dayi-G32 \
  --tensor-parallel-size 2 --dtype bfloat16 \
  --kv-cache-dtype fp8_e4m3 --attention-backend FLASH_ATTN \
  --linear-backend auto --moe-backend auto \
  --max-model-len 262144 --max-num-seqs 32 \
  --max-num-batched-tokens 8192 --max-cudagraph-capture-size 64 \
  --gpu-memory-utilization 0.8 \
  --enable-prefix-caching --mamba-cache-mode align \
  --speculative-config '{"method":"qwen3_5_mtp","num_speculative_tokens":3}' \
  --trust-remote-code --host 0.0.0.0 --port 8000
```

A checkpoint-specific reasoning parser may be added independently. The checkpoint
uses `<ggthink>` markers: a parser for literal `<think>` alone will not split
these markers correctly. The wheel retains reasoning_content as an alias of
reasoning when the configured parser emits reasoning.

For V1 requests with MTP and prompt logprobs, the runner preserves target hidden
states before drafting can reuse their CUDA Graph memory. Ordinary generation
without prompt logprobs takes no additional copy.

## Packaging and validation

Use tools/sm90_release/build_moe.py and package_wheel.py. The builder compiles the
complete MoE extension, including G32 Linear kernels; packaging reuses unmodified
v0.29.0 native libraries for other components and audits their hashes. It does not
recompile every upstream extension. The package targets CPython 3.12, CUDA 13.2,
Torch 2.13.0+cu132 and Linux x86_64. Existing environments need matching
requirements; packaging does not install or alter them.

Regression tests live in tests/quantization/test_sm90_g32.py. Real-checkpoint
loader, numerical, generation and stress evidence is kept alongside the release
artifact. Do not interpret a small generation suite as a guarantee against all
model-level repetition or as a full benchmark accuracy score.
